## Первые команды

```bash
npm install                 # package.json уже на месте
npm run check               # 676 пар через шесть проверок
node tools/data-check.js    # данные доходят до разметки
node tools/smoke.js         # сервер отвечает на пять вызовов
```

## Проверить, что движок жив

```js
import { ST } from './src/engine.js';
import { CATS } from './src/elements.js';
const svg = CATS[0][1].find(e => e[0] === 'kpi')[2](ST.glass);
console.log(svg.slice(0, 80));
```

Должно напечатать начало SVG. Если `t is not defined` — сломан импорт
в `elements.js`, он забирает всё через `import * as ENG`; см. ТЗ.md,
раздел «Известная особенность сборки».

## Что дальше

1. Перевести на данные оставшиеся 23 элемента — те, где литералы рассыпаны
   по телу функции. Порядок такой: собрать содержимое в один массив в начале
   функции, добавить второй аргумент, подставить `ряды`/`строка`, подписи
   пропустить через `ужать`/`ужатьНабор`, при переменном числе рядов —
   `рост()` и `wrapSvgH`. После каждого элемента гонять
   `node tools/audit.js --snapshot <файл>`: разошедшихся пар должно быть 0.
   Сервер править не нужно, он подхватит сам.
2. Два известных замечания, которые не лечатся данными: у `aurora` тёмный
   акцент на подписи поверх поля, у `retro` подпись квадранта цикла подходит
   к кольцу ближе 10px на длинном тексте. Оба видны в `data-check`.
3. Состояние стиля уже **по ключу сессии** — при переезде на HTTP меняется
   только транспорт.

Примеры из `examples/` стоит закоммитить: Claude Design просит живые
образцы, а не только спецификации.
