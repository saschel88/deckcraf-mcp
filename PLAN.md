# План дальнейшей работы

> **Исполнителю:** задачи идут по порядку, каждая заканчивается зелёными
> проверками и коммитом. Отметки `- [ ]` — для отслеживания.

**Цель:** довести библиотеку до состояния, когда любой из 52 элементов
принимает данные пользователя и честно сообщает, что с ними сделал.

**Подход:** данные заходят вторым аргументом в саму функцию отрисовки.
Подставить текст снаружи нельзя: у диаграмм подпись и геометрия берутся
из одного числа. Без данных разметка обязана совпадать с прежней побайтово —
это и есть страховка от того, что 676 образцов поедут.

**Основа:** Node ≥18, `@modelcontextprotocol/sdk`, транспорт stdio.
Ни браузера, ни сборщика.

**Спецификация:** `ТЗ.md` — постановка и принятые решения.
`ГДЕ-ЧТО.md` — карта файлов. `ЗАМЕТКИ.md` — состояние работ.

## Общие ограничения

Действуют в каждой задаче без напоминания.

- **`src/engine.js` не трогать.** Токены, стили, помощники — готовы.
- **Побайтовая совместимость.** `npm run check` обязан говорить
  «разошлись 0». Если разошлось хоть что-то — правка неверна, а не эталон.
- **`npm run baseline` не запускать.** Он затирает доказательство
  совместимости, и заметить это будет уже нечем.
- **Имена полей — из договора** в `spec/elements.json`, не выдумывать.
  Посмотреть договор: `node -e "const j=require('./spec/elements.json');
  console.log(JSON.stringify(Object.values(j['элементы']).find(э=>э.id==='ИД')['данные'],null,1))"`
- **Пороги выводить из геометрии, а не подбирать константой.** На этом
  обожглись дважды: рост холста упирал содержимое в кромку, а порог,
  посчитанный для полосы в 9px, ломался у retro с полосой в 10px.
- **Новые файлы называть латиницей.** Содержимое остаётся русским.
- **Четыре проверки после каждой задачи:**
  `npm run check` · `npm run data` · `npm run smoke` · `npm run host`

## Общий порядок перевода элемента

Отработан на 29 функциях. Повторяется в задачах 2–7, здесь описан один раз.

1. Собрать зашитое содержимое в один массив в начале функции.
2. Добавить второй аргумент: `function elX(s, дан)`.
3. Подставить через `ряды(дан && дан.поле, образец, максимум)` для массивов
   и `строка(дан && дан.поле, образец)` для строк. Образец остаётся значением
   по умолчанию — иначе побайтовое совпадение потеряется.
4. Подписи пропустить через `ужать` (одна строка) либо `ужатьНабор`
   (единый кегль на ряд).
5. Если число рядов переменное — посчитать визуальный низ, звать `рост()`,
   закрывать `wrapSvgH(s, o, hh)` вместо `wrapSvg`, фон рисовать
   `frameH(s, hh)` вместо `frame`. При hh = 190 они совпадают побайтово.
6. `npm run check` — «разошлись 0».
7. Добавить элемент в `Д` внутри `tools/data-check.js` и прогнать
   `npm run data`. Подписи брать длинные и русские — «Затраты на персонал»,
   «НАО Госкорпорация»: короткие ничего не проверяют.

Сервер править не нужно. Он сличает результат с отрисовкой без данных
и снимает предупреждение сам, как только элемент начинает данные принимать.

### Разобрано 22 августа: причин три, и только одна про описания

**Причина первая — основа слова слишком длинная. Дефект алгоритма.**

`основа(w) = w.slice(0, max(4, min(5, len)))`. Для слова из пяти букв это
**всё слово целиком**, и падеж делает его чужим:

```
«цифра» ↔ «цифру»   основы цифра / цифру   →  не совпали
«одна»  ↔ «одну»    основы одна  / одну    →  не совпали
```

`bignum` не находится по запросу «одна цифра», хотя в его назначении написано
«предъявить **одну цифру**». Дословное совпадение по смыслу, промах по буквам.

Бьёт по словам в четыре-пять букв — в русском это огромный класс: цифра,
сроки, доля, поток, этапы, доход. Слова от шести букв обрезаются до пяти
и падежи у них сходятся; короткие — никогда.

**Причина вторая — таблица переадресации работает против нас.** Описана ниже,
в шаге 2. Сто сорок четыре готовые записи поднимают не тот элемент.

**Причина третья — область.** Замерено отдельным прогоном на 15 запросах
из областей, которых в `применять` нет вовсе — медицина, образование,
логистика, сельское хозяйство, ЖКХ:

```
знакомые области (25 запросов): первым 15, мимо 4
незнакомые     (15 запросов): первым  7, мимо 6
```

Разница настоящая. Но **два промаха из шести повторились** из первого прогона
с другими словами: `roadmap` не нашёлся ни на «этапы проекта со сроками»,
ни на «этапы посевной со сроками»; `area` — ни на «нагрузка за год», ни на
«заболеваемость за сезон». То есть даже в незнакомой области мешала лексика,
а не предметная область.

**Отсюда порядок: алгоритм → словарь → области.** Первые два бесплатны
и не трогают описания. Третье может размыть границы между элементами,

### Задача 19. Пределы в договорах рассчитаны под прежнее поведение

Найдено замером наряда 17а, 25 августа. Не следствие пола — он лишь сделал
это видимым.

**На пробной русской фразе 78 полей из 91 обрезаются на своём собственном
объявленном пределе.** Тридцать девять из них — `*.title`, которых пол
не касается вовсе.

Записанное здесь сперва число 45 было верно для кода **до пола**: проверено
прямым прогоном одной величины на двух срезах. Разница в 33 поля — неучтённая
цена наряда 17а, всплывшая при замере наряда 19. То есть договор обещает модели-
сборщику длину, которая не влезает, и обещал её ещё до всех правок меры.

Четыре поля несвежи и при этом задеты полом: `bignum.eyebrow`,
`statcard.label`, `divider.eyebrow`, `chapter.eyebrow`. Это и есть разница
между 37 и 33 в замере наряда 17а.

**Почему это важнее, чем кажется.** Предел в договоре — единственное, чем
модель-сборщик располагает, решая, влезет её текст или нет. Предел, при
котором текст обрезается, — не предел, а ложное обещание: модель уложится
в него и всё равно получит многоточие.

**Цена уже уплачена и видна.** После наряда 17а в образцах библиотеки
215 новых многоточий (`ЗАТРА…`, `СКОРОСТ…`, `TOGAF 9 · IPMA · 10 ЛЕТ В …`),
ни одна прежняя обрезка не исчезла. Это утверждённая владельцем плата
за читаемость, но выглядит она теперь в самих образцах, то есть в том, что
пользователь получает на `draw` без данных.

**Чья задача.** Модели-сборщика: она читает предел и верит ему. И зрителя:
многоточие в образце — это то, что он увидит на слайде.

**Файлы:**
- Изменить: `spec/elements.json` — пределы 91 строкового поля
- Изменить: `tools/data-check.js` — проба, что предел не приводит к обрезке

**Порядок.** Предел выводить измерением: наибольшая длина, при которой поле
на своём объявленном кегле и при нынешнем поле ужатия укладывается без
многоточия. Не подбирать и не округлять на глаз — в этом проекте на подборе
констант обжигались.

**Осторожно с образцами.** Пределы в договоре эталон не двигают, но правка
образцов — двигает. Если для проверки понадобится укоротить `ОБР_*`,
это отдельное решение владельца, а не попутная правка.

### Решение по задаче 19, 25 августа: предел считается под выбранный стиль

Замер шага 0 показал, что **один предел в знаках не может обслуживать
тринадцать стилей**. Разброс по 13 стилям: медиана 25%, наибольший 41%,
у 81 поля из 91 больше пятой части. В знаках заголовок держит 44 в `flat`
и 26 в `line`, а объявлено 29 — число неверно в обе стороны сразу.

Три варианта наряда замерены, и замер убил один из них:

```
черновик пробы «подпись в предел укладывается без многоточия»
   как сейчас        175 нарушений
   вариант А           0
   вариант Б          79     ← не выдерживает собственной пробы
```

Б мерился смешанным регистром, а в семи стилях `t()` поднимает регистр
**после** подгонки — то же ложное обещание, которое задача велит убрать.
При этом Б щедрее А всего на 5%.

**Владелец выбрал четвёртый вариант, родившийся из замера: предел считается
под тот стиль, который уже выбран.** `describe` знает стиль — он и сегодня
возвращает `стиль`, `доступен_в_стиле`, `заметки_по_стилям`, — а стиль
выбирается раньше всего: без `start` не работает ни один инструмент. Значит
одному числу не нужно обслуживать тринадцать стилей вовсе.

Условия, поставленные к исполнению:

- **второй меры не заводить** — предел считать самой библиотекой, тем же
  `ужать` на настоящем стиле; трое двойников меры уже однажды разъехались;
- **капс учитывать** — иначе предел лжёт ровно там, где лгал раньше;
- `сверитьДанные` обязан считать по стилю, иначе ругается по одному числу,
  а рисует по другому;
- **образец длиннее нового предела — это находка, а не повод править
  образец**;
- назвать, на скольких полях предел **вырос**: в `flat` заголовок держит 44
  против объявленных 29, то есть где-то мы отнимали у автора зря.

### Задача 20. Массивы строк обещают больше, чем держат

Найдено нарядом 19, подтверждено его проверкой независимым замером.

**Одиннадцать из двенадцати полей «массив строк» обещают больше, чем держат,
во всех тринадцати стилях сразу.**

```
chapter.lines   обещает 53   держит 33–43
agenda.items    обещает 46   держит 32–42
heat.rows       обещает  3   держит  2
```

**Поправка 25 августа, замер наряда 20.** Полей не двенадцать, а **тринадцать**:
тринадцатое — `trans.rows`, у него «длины» нет вовсе, и `сверитьДанные` держит
проверку массива за воротами `if (длина && …)` — поле молча выпадает. Тот же
класс, что закрыло ревью наряда 19 у трёх строковых полей.

И `roadmap.cols` — **не исключение, а главный случай**: обещанные 8 знаков
держатся только до четырёх колонок, а договор разрешает до шести (пять → 7,
шесть → 6). Наряд 19 мерил его на образце из четырёх. Значит обещают больше,
чем держат, все тринадцать.

**Развилка формы схлопнулась.** У одиннадцати полей из тринадцати предел
от числа строк не зависит вовсе; зависит у двух — `roadmap.cols` (46 → 6,
падение 87%) и `area.labels` (45 → 9, 80%). Решено ведущим без обращения
к владельцу, потому что цена мелка: **таблица «строк → знаков» у двух
зависимых полей, одно число под выбранный стиль — у одиннадцати остальных.**
Таблица стоит десять строк договора; «предел по худшему» отнял бы у `roadmap`
сорок знаков при одной колонке ради правды про шесть.

Третий случай зависимости особый: у `heat.cols` число подписей задаёт
**ширина соседнего поля** `matrix`, а не своё, и при шести колонках обещанные
10 знаков превращаются в 5.

**Почему их не взяла задача 19.** Там предел вычисляется парой «поле и стиль»;
у массива он зависит ещё и от **числа строк в массиве**: три пункта повестки
и семь пунктов повестки получают разную ширину и разный кегль, потому что
`ужатьНабор` выдаёт всему набору общий кегль по самой длинной строке.
Парой поле/стиль такой предел не описывается, и подставлять сюда число
задачи 19 значило бы заменить одно ложное обещание другим.

**Форма договора для них — открытый вопрос.** Возможные:
предел как функция от числа строк (таблица «строк → знаков»); предел
по худшему числу строк; предел на строку плюс предел на суммарную длину.
Выбирать после замера, как в задаче 19, и решение за владельцем.

**Замечание к замеру.** Проверяющий наряда 19 показал, что мерить массив
одинаковыми строками нельзя: `vec.clusters` при одинаковых даёт 21–28,
при различимых — 12–16, потому что замер удовлетворяется одним уцелевшим
узлом. Перемерено исполнителем: при объявленных **35** поле держит 12–16,
то есть обещает вдвое-втрое больше, а не в полтора раза. Остальные
одиннадцать полей на различимых строках дали те же числа — маскировка
была только там, где слоты разной ширины. Мерить только различимыми.

**Файлы:**
- Изменить: `spec/elements.json` — двенадцать полей типа «массив строк»
- Изменить: `src/index.js` — `сверитьДанные` и `describe` для этих полей
- Изменить: `tools/data-check.js` — проба на предел массива

### Задача 22. Пять наших образцов нарушают наш же договор

Найдено нарядами 19 и 20: четыре образца вчера, пятый сегодня.

**Четыре образца длиннее предела своего стиля**, все — только в семи стилях
с капсом. Число установлено перемером отрисовкой, 105 полей × 13 стилей:
наряд 19 назвал пять, но `speaker.role` по числам длиннее предела, а по
разметке доезжает целым — латиница уже пробной фразы. Список смешивал

```
rag.store        «Векторная база»                14 при 13
egov.note                                        53 при 44
speaker.line1    «TOGAF 9 · IPMA · 10 лет в ИТ»  28 при 21
venn.center      «трансформация»                 13 при 11
```

**Почему это важнее, чем пять строк.** Образец — то, что пользователь получает
на `draw` без данных, и то, по чему модель-сборщик судит, как элемент выглядит.

**Осторожно: правка образцов двигает эталон.** Это отдельное решение владельца,
а не попутная правка, и цена должна быть названа парами до начала работ.
Пять образцов × семь стилей с капсом — до 35 пар, но проверить надо замером:
в стилях без капса образцы влезают и меняться не должны.

**Развилка.** Либо укоротить образцы под самый тесный стиль — тогда в шести
стилях без капса образец станет короче, чем мог бы; либо признать, что образец
живёт по своим правилам, и вывести его из-под проверки, назвав это в договоре.
Первое честнее, второе дешевле.

### Задача 23. «Массив массивов» не сверяется — и сверх того говорит неправду

**Дополнено ревизией наряда 29, 27 августа.** Найден второй случай того же
рода, и причина названа точно: **`heat.matrix` объявлен «размером 4×5»,
а не «количеством»** — поэтому `рамки()` его не меряет вовсе. Матрица 7×8
режется до 5×6 **молча, на обоих ярусах**. То есть беда не в том, что
проверка слаба, а в том, что поле объявлено формой, которой проверка
не знает.

Названо нарядом 20 как остаток, **ухудшено его проверкой**: беда не в том,
что сервер молчит, а в том, что он говорит неверное.

У полей типа «массив массивов» — матрица `heat` и подобные — «размер»
не сверяется ничем: матрица в шесть столбцов пройдёт молча и уронит предел
подписи до пяти знаков.

**А при матрице 4×6 сервер прямо врёт.** Он говорит «лишние 1 в разметку
не попадут» — а шестая подпись рисуется. И молчит о том, что обрезаны
оказались все шесть. Проверено отрисовкой.

Общая причина, названная проверяющим и стоящая отдельной строки:
**предел в предупреждении меряется по образцу чужих полей.** Поле само
по себе не решает, сколько ему дано, — на его вместимость влияет то,
что передано в соседние. Правило надо записать в код, а не держать
в головах.

Смежно с этим: у `heat.cols` число подписей задаёт **ширина соседнего поля**
`matrix`, а не своё. Наряд 20 нарочно не стал вести его таблицей — таблица
индексируется числом строк в самом поле, и подпирать правило исключением
было бы хуже беды. Зависимость названа заметкой в договоре и ждёт своей формы.

### Закрытие задачи 18: чего стоило сделать прогон достоверным

Инструмент готов: `npm run diff`, **4056 сравнений** на прогон, шесть наборов
данных, ни одного временного файла — старый код берётся `git show`.

**Что он ловит, а `check` нет — измерено дважды, разными людьми.** Подсадка
промаха на единицу в `ряды()`: `check` — «пар 676, разошлись 0», зелёный;
`diff` — на образцах 0, **на данных 572 расхождения в 44 элементах**.
Проверяющий повторил своими тремя подсадками — в геометрию, в текст, в цвет,
— инструмент увидел все три.

**Главное, что пришлось чинить, — он сам умел молчать.** Проверяющий сломал
разбор данных: две трети покрытия отпали, а прогон напечатал «расхождений 0,
ни на одном наборе» и вышел с нулём.

Это **пятый за день** случай одной беды: проверка печатает ноль, потому что
не смотрела. До него — опечатка в регулярке зазора, сторож числа по вхождению
подстроки, ворота у трёх строковых полей, ворота у массивов. Инструмент,
заведённый сторожить от тихих потерь покрытия, не имел права терять покрытие
тихо.

### Задача 26. «Гарантия» не держится на соседних числах

Найдено код-ревью наряда 24, 26 августа. Наряд принят — это остаток,
а не дефект правки.

Правило, записанное задачей 23, звучит так: **предел меряется по образцу
чужих полей**. У подполей массивов объектов «чужие поля» перестали быть тем,
чего автор не шлёт: он шлёт их сам, и в законных границах договора.

```
funnel.levels.value   обещает 8   при законном k=0.2  влезает 5
                                  при законном k=0.05 влезает 4
bub.bubbles.label     обещает 4   при законном r=15   влезает 3 в шести стилях
```

Наряд 24 поставил верный диагноз — немонотонность `funnel.levels.value`
(3→15→8) означает, что предел определяет не число рядов, — и взял худший
случай **только по числу рядов**. По соседним числам худший не брался.

**Что это значит.** Слово «гарантия» в договоре пока сильнее того, что
мы можем обеспечить: модель уложится в предел, пришлёт законное соседнее
число и получит многоточие.

**Развилка, и выбирать после замера.** Брать худший по всем законным
сочетаниям соседей — предел упадёт, возможно сильно. Или назвать в договоре,
от каких соседей предел зависит, и отдавать его через `describe`, который
эти числа уже видит, — так же, как задача 19 решила вопрос со стилем.
Второе точнее и дороже.

**Смежное, из того же ревью.** Восемнадцать числовых подполей рисуются
подписями и длиной не описаны **вовсе**: `сверитьДанные` про них молчит,
проба их не смотрит. Это те же ворота, только по типу поля, а не по наличию
числа.

**Мелочи оттуда же:** замечания сервера ругают свёрнутый `faq.items.a`,
которого в разметке нет (мера маску живых слотов знает, замечания — нет);
форму «не ограничена» выбирает потолок меры в 140 знаков, а не свойство
элемента.

### Дефект буквы наряда 24, признан ведущим

Приёмочная строка наряда велела гнать `npm run diff` без довода. Без него
инструмент берёт предпоследний коммит, а последний шаг трогал только файл

### Задача 27. Разведка по шести MCP-серверам вокруг SVG

Заведена владельцем 27 августа. Вопрос поставлен им так: **есть ли там

**Порядок — по близости к нашим открытым вопросам, а не по списку.**

**1. `mcp-mermaid-svg` — автоматическая раскладка.** Самый ценный. Принимает

как ведут себя при росте числа узлов — растят холст, жмут текст или режут.

**2. C1 MCP (Thesys) — канал доставки.** Рисует SVG **прямо в интерфейсе
клиента**, а не отдаёт XML текстом. Наша слепая зона: мы отдаём сырой SVG,
и живой прогон владельца кончился файлами на диске. Вопросы: как устроен
ответ инструмента; что видит человек и что видит модель; переносимо ли это
к нам без переезда на HTTP (переезд владелец из плана снял).

### Закрытие задачи 28, 27 августа: три высоких дефекта закрыты

**Д-2, `describe` спорил сам с собой.** Восемь пар. Причина не в недосмотре:
`ALLOW` заполнена только для шести переходных слайдов, и там перечислены

константа `true` на 676 пар. Исключение переехало в машиночитаемый ключ

всегда» не отменяли; если владелец сочтёт исключение запретом, верный ход

#### Уроки круга правок

**Одно понятие жило в трёх формах между инструментами.**
`не_рекомендуется_в_стиле`: `catalog` отдавал строку и вовсе не клал ключ
на годной паре, `find` и `describe` — объект. Починив «одно поле — один
вопрос» внутри `describe`, завели то же расхождение **между инструментами**.
Причина, названная исполнителем: пробы сличали **наличие** пометки, а не
её **форму**, и проверяли трёх тремя отдельными утверждениями — каждое
по отдельности проходило.

**Доминанта обрела письменное основание.** «Доминанта — это `s.pos`» нигде
не была записана; токен, который называется акцентным (`ac`), лежит
на «Спланировать». Основание записано словарём ролей, который у договора
уже был (`spec/tokens.json → роли`), а имя токена положено рядом нарочно:
**утверждение договора должно поверяться замером, а не пересказом.**
Из пробы ушли все цвета и все имена токенов; проверяются все четыре слота,
48 сверок вместо одной.

**Проба, утверждавшая невозможное.** Четвёртая проба формы была поставлена
после `start`, а стиль сессии не снимается — она утверждала то, чего быть

### Договор против кода: разбор двух случаев

Заведено по вопросу владельца — почему при расхождении мы всегда объявляем
правым код. Ответ: потому что правка договора бесплатна, а правка отрисовки
двигает эталон. **Дешевизна подменила верность.** Разбор двух случаев:

**`roadmap` — прав код, доказано историей.** «Подпись слева от полосы» —
не замысел, а **описка возрастом в сутки**: внесена внутрь массовой правки
54 объявлений длины (наряд 24) и снята на следующий день. Строка композиции
«не подписывать полосы снаружи — подпись внутри» стоит **с первого коммита
и не менялась ни разу**; геометрия подписи **старше репозитория** — та же
в прототипе. Если бы прав был договор: 9 знаков при любом `len`, треть задачи
26 исчезает, цена 13 пар, но `roadmap.cols` теряет три знака («Октябрь» →
«Октяб…»).

**`heat` — 4×5 похоже на замысел, и возврат стоит НОЛЬ пар.** В прототипе
матрица вбита числами 4×5, ячейка фиксирована. Срезы 5×6 появились вместе
с приёмом данных и рядом с зажимами — похоже на **сознательный запас**.
Ошибка договора была не в числе, а в слове: «размер» у поля, которое размера
не имеет.

**И прежнее число мертво:** замер задачи 23 обещал «13 пар, `baseline`
придётся пересобирать» — это была **оценка на глаз**. Решение принималось
при цене, завышенной с нуля до тринадцати.

**Резать `cols`/`rows` «по своему договору» было бы хуже:** при матрице
шириной 2 пять подписей встали бы под двумя столбцами — молчание сменилось бы
враньём. Рез по соседу верен геометрически; **порочна его беззвучность**:
доезжают две подписи из шести, **замечаний 0**. `ряды()` — единственный путь
потери данных, не обретший голоса после наряда 29. Живой пример —
`el-heat-partial.svg` в корне.

**Щель, оставленная нарядом 23а:** `matrix` разрешает 6 столбцов, `cols`
объявляет «количество: 5» — шестой столбец законен и ничем не подписываем.

Мысль владельца, 25 августа. **Отложена до разбора плана по его же решению**;
записана, чтобы не потерялась, и обсуждена наполовину.

**Суть.** Наш потребитель — модель, а не человек. Человеку с готовым слайдом
остаётся только сократить текст. У модели есть ход, которого у него нет:

Задача 12 дала половину ответа — машиночитаемое «требует 238.4 при доступных

**Мы и мерили не в ту сторону.** Задача 19 считала предел, чтобы ограничить
автора. А предел — прежде всего признак для подбора: при 37 знаках заголовка
вопрос не «чем жертвовать», а «какой элемент держит 37 в этом стиле».

**Машина уже построена.** `пределЗнаков(отрисовка, поле, стиль)` даёт предел
для любой пары; один прогон даёт таблицу 94 × 13, по которой «кто держит
37 знаков в роли заголовка при стиле line» — просто выборка.

### Четыре решения, на которых всё держится

**1. Что считать «той же ролью».** Не заводить таксономию: `find` уже
ранжирует по смыслу, а в договоре есть `назначение`, `применять`,
`не_применять`, `категория`. Взять назначение самого элемента как запрос,
прогнать через нынешний `find`, оставить тех, кто близок по смыслу **и**
держит длину. Тогда замена — всегда та, которую `find` и так счёл бы уместной.

**2. Стиль в совет не входит.** Самый сильный рычаг вместимости — стиль:
заголовок держит 44 знака в `flat` и 26 в `line`, разница больше любой замены
элемента. Но стиль один на презентацию, и совет «возьмите другой стиль»
означает перекрасить колоду ради одного слайда. Советовать только внутри
выбранного стиля.

**3. Советовать только при переполнении**, полем в уже существующей
машиночитаемой записи. `describe` не знает, какой текст у модели на руках,
и совет заранее выродится в справку.

**4. Пустой список замен — законный ответ.** Если ни один близкий по смыслу
элемент не держит нужную длину, честно сказать «сокращать придётся, замены
нет». Это должно отличаться от «мы не искали».

### Задача 17. Политика автофита записана числами, а не подразумевается

- [ ] **Шаг 5. Переменное число рядов: отбрасывать хвост, а не сжимать всех**

в ширину, и возвращает **пару**: подогнанный текст и подобранный кегль.

Сто вызовов из ста двенадцати берут только текст:

```js
o += txt(s, cx, base+22, t(s, ужать(label, bw, 13)[0]), 13, ...);
//                            подобранный кегль ─┘ выброшен  └─ рисуем исходным
```

Замер по `src/elements.js`:

```
ужать(...)[0] — кегль отброшен    100
ужать(...)[1] — кегль взят          1
через деструктуризацию             11
```

**Что из этого следует.** `ужать` считает: «чтобы 46 знаков влезли в 228px,
нужен кегль 9». Возвращает текст целиком и кегль 9. Вызывающий рисует его
кеглем 13 — и строка выходит 329px вместо 228, вылезая за холст на 65px.

Проверено на `kpi.label`: правый край текста **365 при холсте 300**.
Предупреждений ноль — с точки зрения `ужать` всё влезло.

**Отсюда же неверные пределы.** Вчерашние лимиты измерялись «подавать строки
растущей длины, пока не появится „обрезаны“». Обрезка наступает, когда `ужать`
упирается в пол кегля — то есть предел меряли **при уменьшенном кегле**,
а рисуют полным. Отношение пола к исходному — 0.72, отсюда завышение примерно
в 1.4 раза, что и совпадает с наблюдением живого прогона «завышены в полтора-два».

Замер: **73 поля из 90 с объявленной длиной вылезают за холст на своём же
объявленном пределе.**

**Починка ничего не стоит.** Инструментировал `ужать` и прогнал все 676 пар:

```
пар отрисовано: 676 | срабатываний со сжатием или обрезкой: 0
```

На образцах текст всегда влезает исходным кеглем, значит `ужать` возвращает
кегль неизменным, и подстановка возвращаемого значения **не меняет ни байта
образцовой отрисовки**. Эталон не пересобирается.

## Что вынесено в отдельный план

**Переезд на HTTP снят с плана 21 августа** — по решению владельца, после
разбора действующих лиц. Причина: у этой работы нет ни человека, ни зрителя
слайда. Она нужна там, где к одному серверу обращаются параллельно; в связке
«один человек, один Клод, один локальный процесс» такого не бывает.

Разделяемая ячейка стиля при этом никуда не делась: у stdio нет `sessionId`,
ключ сеанса — константа, и четыре параллельных агента 21 августа переписали
стиль друг другу. Практический случай закрыт поштучным `style` в `draw`:
передал явно — нарисуется им, состояние сессии не трогается.

Вернуться к этому придётся, если появится второй одновременный потребитель:
облачный хост, несколько агентов, несколько человек на одном процессе.
Код к переезду готов — `ключСессии(доп)` уже читает `доп?.sessionId`,
карта `СЕССИИ` уже по ключу. Менять пришлось бы транспорт и запуск,
а не инструменты.

**Два замечания, которые данными не лечатся.** `aurora/bars` — тёмный
акцент подписи поверх поля. `retro/cycle` — подпись квадранта подходит
к кольцу ближе 10px на длинном тексте. Оба видны в `npm run data`,
оба свойства самих стилей. Лечится правкой стиля, а не элемента,
и требует отдельного решения — менять ли стиль ради одного элемента.

**Точность измерения текста.** Ширина считается как
`длина × кегль × 0.55`; для кириллицы это грубо, отсюда пограничные
замечания вроде 15.9px при норме 16. Точность даст только таблица метрик
Inter. Работа небольшая, но затрагивает все 52 элемента разом и потому
не должна идти вперемешку с переводом на данные.

## Порядок и почему такой

Задача 1 идёт первой, хотя выглядит документацией. Она делает `describe`
пригодным для того, ради чего он написан, и заодно даёт числа, которые
понадобятся в задачах 2–7 при подгонке.

Задачи 2–7 отсортированы по возрастанию риска: сначала подстановка строк,
где сломать нечего, потом позиционирование, потом пересчёт геометрии,
последним — `trans`, которому нужен новый договор.

Задача 8 идёт последней намеренно: правило роста проще применять, когда
все элементы уже принимают данные и видно, какие ряды бывают переменными.
