# Постановка задачи · MCP-сервер библиотеки SVG-элементов

## Что делаем

Локальный MCP-сервер, который по запросу возвращает **либо готовый SVG-элемент,
либо его полное описание** для Claude Design. Работает в рамках одного выбранного
стиля на всю сессию.

## Почему Node, а не Python

Код отрисовки уже существует на JavaScript: 105 КБ, 52 элемента, 13 стилей.
Проверено — **ни одной зависимости от браузера**: используются только `Math` и `Object`,
всё работает в чистом Node. Порт на Python означал бы переписать всё заново
и повторно собрать дефекты, которые уже вылечены шестью проверками.

## Стек

| | |
|---|---|
| среда | Node 18+, ES-модули |
| протокол | `@modelcontextprotocol/sdk`, транспорт **stdio** |
| клиент | Claude Desktop (локально, без сети и авторизации) |
| зависимости | только SDK; отрисовка и проверки — свой код |

Транспорт stdio выбран потому, что сервер локальный: Claude Desktop сам запускает
процесс, публичный HTTPS и OAuth не нужны.

проверка глазами хоста, сборка страницы для глазной проверки).

## Инструменты

**Об именах.** Латиницей называются и имена инструментов, и **имена полей
в схемах**; всё остальное русское: заголовки, описания, ключи ответа.
Причина внешняя — Anthropic API проверяет шаблоном `^[a-zA-Z0-9_.-]{1,64}$`
не только имя инструмента, но и каждый ключ свойства в `input_schema`.

Изначально русские имена параметров (`стиль`, `запрос`, `данные`) были
объявлены синонимами латинских. Это оказалось нерабочим: при первом же
живом подключении API отверг **весь** список инструментов ошибкой 400,
отключив заодно и остальные серверы сессии. Приём синонимов в разборе
аргументов остался, но схема их не объявляет — незаявленное поле хост
всё равно не отправит.

### 1. `styles` · стили
Без параметров. Возвращает 13 стилей: название, суть, цветовая модель,
требования к фону. Нужен, чтобы выбрать.

### 2. `start` · начать
Параметр: `style` (перечисление из 13).
Фиксирует стиль в состоянии сессии. Возвращает его полную спецификацию
и требования к фону.

**Правило: пока стиль не выбран, `find`, `describe` и `draw` возвращают ошибку.**
Это делает правило «один стиль на презентацию» невозможным нарушить,
а не рекомендацией в документе.

### 3. `catalog` · каталог
Параметр: `category` (необязательный — один из семи разделов).
Возвращает весь состав библиотеки по разделам: id, название, назначение,
пометку «принимает данные».

Единственный инструмент, кроме `styles`, работающий **до** выбора стиля:
«что у вас есть» спрашивают до того, как выбирают стиль, а не после.
Если стиль всё же зафиксирован, каждый элемент помечается доступностью в нём.

Инструмент дописан после живой проверки: первым же вопросом человека
оказалось «покажи, какие есть элементы», и обслужить его было нечем —
`find` отдаёт 1–3 кандидата под уже сформулированную задачу, а не каталог.

### 4. `find` · найти
Параметр: `query` (строка — что нужно показать человеческими словами).
Возвращает 1–3 кандидата: id, название, назначение, поле «не применять».

Поиск по полям `назначение`, `применять` и категории. Поле «не применять»
возвращается всегда — без него выбор идёт по названию, а не по смыслу.

### 5. `describe` · описать
Параметр: `id`.
Возвращает полное описание для Claude Design: композиция в относительных
величинах, договор о данных, требования к фону выбранного стиля, запреты.
Отдельным полем `принимает_данные` сообщает, дойдут ли данные до отрисовки.

Если описание элемента ещё не готово — честно вернуть
`{"описание": "не готово", "нарисовать_можно": true}`. На сегодня в
`spec/elements.json` описаны **все 52**, ветка осталась на случай новых.

### 6. `draw` · нарисовать
Параметры: `id`, `data` (по договору элемента), `style` (необязательный).
Возвращает разметку, **стиль, которым отрисовано**, размер холста, требования
к фону и предупреждения шести проверок. Проверки отрисовку не блокируют.

**Про `style` и разделяемое состояние.** Стиль по умолчанию берётся из `start`,
но `style` в запросе рисует им, не меняя выбор сессии. Это не удобство,
а необходимость: у stdio-транспорта нет `sessionId`, ключ сессии всегда один,
и карта состояний вырождается в единственную ячейку на весь процесс. Хост
поднимает сервер один раз и раздаёт подключение всем своим агентам — два
параллельных потребителя переписывают стиль друг другу молча.

Найдено живой пробой: четыре агента с чистым контекстом получили чужие стили
и выдали четыре разных неверных диагноза — «фиксация живёт одну операцию»,
«стиль слетает», «гейт не работает», «сломан элемент fmatrix». Ни один не
дошёл до причины, потому что снаружи она неотличима от отказа элемента.
Отсюда три следствия, все реализованы: ответ обязан называть стиль; стиль
можно задать поштучно; расхождение с зафиксированным попадает в предупреждения
(запретить смешение нечем — `start` и так позволяет переключаться, но сделать
его видимым можно).

**Немые потери данных.** Той же пробой выяснилось, что отрисовка молча
отбрасывает лишнее: восемь рядов при договорных «2–5» превращались в пять,
а подпись «Первый контакт» — в «Первый конта…», и оба раза статус был «успех».
Теперь превышение количественных рамок договора и всякая обрезка подписи
попадают в `предупреждения`. Многоточие — надёжный признак: в образцовых
отрисовках всех 676 пар его нет ни одного.

## Проверки перед выдачей

Каждый отрисованный SVG прогоняется через шесть проверок. Результат
возвращается в `предупреждения`, отрисовка не блокируется.

| проверка | что ловит | порог |
|---|---|---|
| разметка | NaN, пропавший текст | — |
| нижний отступ | расстояние до кромки карточки | ≥ 16px |
| зазор подпись↔фигура | отдельная подпись под фигурой | ≥ 10px |
| текст в фигуре | отступ и центровка | ≥ 4px, перекос ≤ 3px |
| контраст | подпись против заливки под ней | Δ светлоты ≥ 0.20 |
| тёмный на поле | у стилей без панели | светлота ≥ 0.60 |

Перенесены в `src/checks.js`. Питоновские образцы остались в `checks/`:
`check.py` дал разметку, контраст и тёмный на поле, `measure.py` — нижний
отступ, `gap2.py` — зазор, `inner.py` — текст в фигуре. Пороги и обоснования
лежат в `spec/rules.json`.

Две сознательные правки против образцов. Нижний отступ считается от
фактической высоты холста, а не от константы 176, — иначе рост холста ломает
саму проверку. Наложение строк из `check.py` вошло в проверку разметки:
налезающая подпись и есть пропавший текст, отдельной седьмой проверки ТЗ
не предусматривает.

## Тонкости, которые легко упустить

**Стиль диктует свойства фона, а не цвет.** Границы светлоты для каждого
стиля в `spec/styles.json`, раздел `требования_к_фону`. У нейморфизма
карточка обязана совпадать с фоном — снимать фон нельзя. У Aurora элемент
сам и есть фон.

**Бренд-переходники у стилей разные.** Нейморфизм монохромен, дуотон
двухцветен, брутализм ахроматичен, мемфису нужны столкновения, ретро
квантуется. Одним сдвигом светлоты это не описывается — см. `ADAPT` в engine.js.

**Токены `line` и `track` — разные.** Первый для линий и связей, обязан
быть видимым. Второй для жёлоба шкалы.

**Русские подписи длинные.** «Затраты на персонал» — 19 знаков.
Перенос на две строки реализован в `wrap` и `fitLines`; односложные
слова переносить нечем, там уменьшается кегль.

| | как проверить | состояние |
|---|---|---|
| 1. `draw` отдаёт валидный SVG для 676 пар | `npm run check` | 676 пар, сбоев 0 |
| 2. Без `start` `find`, `describe`, `draw` возвращают ошибку | `node tools/smoke.js` | все три отказывают |
| 3. Подгонка под длинный текст, холст растёт | `node tools/data-check.js` | 145 пар, ни одна подпись не потеряна, холст вырос 20 раз |
| 4. Проверки предупреждают, а не молчат | `npm run check` | 61 замечание на образцах |
| 5. Сервер поднимается настоящим хостом | `npm run host` + живое подключение | 24 пробы без сбоев; под шаблон API приведены и имена инструментов, и имена полей |

Отдельно проверяется совместимость: слепок разметки всех 676 пар до и после
перевода элементов на данные — **разошлись 0**.

## Удалённое развёртывание для коллег

Локальный сервер работает у одного человека. Чтобы им пользовалась команда,
нужен удалённый MCP-сервер: он подключается как пользовательский коннектор
и доступен на всех планах, включая личные.

**Что меняется в устройстве:**

| | локально | удалённо |
|---|---|---|
| транспорт | stdio | HTTP, поток событий |
| выбранный стиль | переменная в процессе | **состояние на сессию** |
| адрес | путь к файлу | публичный HTTPS |
| авторизация | не нужна | OAuth либо токен |

**Главное отличие — состояние.** При локальном запуске стиль можно держать
в обычной переменной: пользователь один. При удалённом коллеги работают
одновременно, и общая переменная означает, что выбор стиля одним человеком
изменит его у всех. Стиль обязан храниться в сессии, ключом которой служит
идентификатор соединения.

**Что стоит предусмотреть сразу**, даже если начинаете с локального:
хранить стиль не в переменной модуля, а в объекте состояния, который
получает ключ сессии. Локально ключ будет один, удалённо — по числу
подключений. Переделка потом дороже, чем закладка сейчас.

Отрисовка и проверки состояния не имеют — они чистые функции,
переносятся без изменений.

**Где разворачивать:** любая площадка с Node и публичным HTTPS.
Отдельная база не нужна, состояние живёт в памяти процесса.

## Известная особенность сборки

`src/engine.js` экспортирует **все** объявления верхнего уровня, а `src/elements.js`
забирает их через `import * as ENG` с деструктуризацией. Сделано намеренно:
список из сорока имён вручную не сопровождается, а при добавлении нового
помощника легко забыть его дописать — и элементы упадут с `is not defined`.
Ровно на этом пакет и сломался при первой сборке.
