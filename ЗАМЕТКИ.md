# Заметки к продолжению

Состояние на 24 августа 2026, конец сеанса. Писалось, чтобы продолжить
с любой машины, не восстанавливая контекст.

## Где остановились

**Перевод на данные закончен.** Все 52 элемента принимают данные пользователя,
подстраивают под них разметку и **говорят, что с этими данными сделали**.
Последнее появилось только что, задачей 12: до неё элемент, увидевший беду
в данных, молчал.

Работа идёт в ветке `elements-data`. `main` остаётся на `68c12ec` и не тронут —
слияние впереди, после того как закроются задачи качества.

```bash
npm install
npm run check     # 676 пар, сличение с эталонным слепком
npm run data      # данные доходят до разметки, элемент подстраивается
npm run smoke     # сервер настоящим MCP-клиентом по stdio
npm run host      # условия запуска: чужой каталог, урезанное окружение
npm run find      # качество поиска на 40 запросах
npm run diff      # что изменила правка: две версии кода на одном движке
npm run baseline  # ПЕРЕСОБРАТЬ слепок — только по отдельному решению
```

Все обязаны заканчиваться без сбоев. `npm run check` обязан сказать
**«разошлись 0»**.

### Чем какая проверка занимается и чего не ловит

| проверка | что доказывает | чего НЕ ловит |
|---|---|---|
| `check` | 676 образцовых отрисовок совпали со слепком побайтово | **всё, что происходит на переданных данных**: слепок снят без них |
| `data` | переданное дошло до разметки, подписи не потерялись, пределы держатся | изменение разметки, которое ни одну подпись не потеряло |
| `smoke` | сервер отвечает по stdio так, как обещает договор | саму картинку: `smoke` смотрит на ответ, а не на разметку |
| `host` | запуск из чужого каталога и с урезанным окружением | всё содержательное |
| `find` | поиск находит нужный элемент на 40 запросах | всё, кроме поиска |
| `diff` | **что именно изменила правка** — две версии кода рядом на шести наборах данных | ничего не сторожит: не говорит, правильно ли изменилось, только что |

`check` и `diff` — не замена друг другу, а два разных вопроса. `check`
сторожит образцы от сдвига и краснеет сам. `diff` не сторожит ничего: он
показывает, что изменилось, а решает человек. Поэтому `diff` возвращает
ненулевой код только когда сличение НЕДОСТОВЕРНО — движок между ревизиями
менялся или стенд не поверился, — а не когда расхождения найдены.

## Чего `npm run check` не доказывает

Это самое важное, что выяснилось за день, и оно ломает привычку.

**`check` сличает 676 отрисовок, и все 676 отрисованы БЕЗ данных.** Он говорит
ровно одно: образцы не поехали. Всё, чем проект занимается с первого дня —
поведение элемента на переданных данных, — этой проверкой не покрыто вовсе.

Наряд 12 изменил 383 строки в `src/elements.js`. Зелёный `check` об этом
молчал. Доказательство собрал проверяющий вручную: поднял старый и новый
`src/elements.js` рядом на один `src/engine.js` и сличил выводы побайтово —
**4564 сравнения**, 52 элемента × 13 стилей в шести режимах (без данных,
со сборщиком, договорные данные, «мутант» с числами `×3+7` и удлинёнными
строками, «всё в минус»), расхождений 0.

**Правишь поведение на данных — гоняй `npm run diff`.** Сличать надо две
версии кода между собой на одних данных, а не код со слепком: такой прогон
не хранит эталона и потому не устаревает. За три дня его собирали заново
четырежды (наряды 12, 16, 17а, 20), и каждый раз он умирал вместе с временным
каталогом проверяющего. Теперь он живёт в `tools/diff-run.js`.

```bash
npm run diff                     # рабочее дерево против прошлого коммита
npm run diff -- <рев>            # против любой ревизии
npm run diff -- <стар> <нов>     # две ревизии между собой
npm run diff -- <стар> <нов> --expect <список>   # сверить множество пар
```

Шесть наборов данных на каждую пару стиль/элемент: образцы, образцы
со сборщиком замечаний, договорные данные `data-check`, все строковые слоты
забиты фразой по объявленному в договоре пределу, «мутант» (числа `×3+7`,
строки удлинены) и «всё в минус» (числа `−|v|−13`). Итого **4056 сравнений**
на прогон, и число сравнений печатается всегда: «расхождений 0» без него
не значит ничего, потому что ноль сравнений тоже даёт ноль расхождений.

Три вещи, которые он делает сам, потому что на них спотыкались руками:

- **сторожит движок.** Старый `elements.js` поднимается на нынешний
  `engine.js` — так и надо, это изолирует правку в элементах. Но если между
  ревизиями менялся сам `engine.js`, сличение врёт, и об этом он говорит
  вслух и возвращает ненулевой код.
- **поверяет стенд.** Каждая сторона сперва прогоняется против эталона
  СВОЕЙ ревизии и обязана дать «разошлись 0». Инструмент, который всегда
  говорит «0», неотличим от исправного.
- **называет набор стилей.** Тринадцать, `iso` исключён. Наряд 20 намерил
  «364 пары» по четырнадцати и получил расхождение с нарядом 19 на пустом
  месте.

Ничего не пишет: ни эталон, ни рабочее дерево не трогает, временных файлов
не создаёт, из сети не тянет — старый код берёт `git show`.

**Что он ловит, а `check` нет — измерено.** В `ряды()` подсажена правка,
теряющая последний переданный ряд. `npm run check` — «пар 676, разошлись 0».
`npm run diff` — на образцах 0, **на данных 572 расхождения в 44 элементах**,
первой же строкой «`flat/bars` узлов текста 11 → 9».

## Главное правило работы с elements.js

Функции отрисовки принимают данные вторым необязательным аргументом, третьим —
собирающий массив для замечаний. **Без данных разметка обязана совпадать
побайтово с прежней.** Гарантию держит `tools/baseline.json` — слепок sha1
всех 676 пар.

**Пересборок за проект шесть, все по отдельному решению, всего 63 пары:**

| что менялось | пар | кто решал |
|---|---|---|
| `chip()` перестал рисовать зашитое «+23%» | 1 | владелец, спрошено явно |
| `column` — шкала от максимума вместо пола в 100 | 13 | владелец, спрошено явно |
| `area` — то же самое | 13 | ведущий, по прецеденту `column` |
| `micro` — зазор подписи | 11 | ведущий, заранее |
| `divider` — нижний отступ | 13 | ведущий, заранее |
| `agenda` — последняя позиция палитры | 12 | ведущий, по прецеденту |

**Седьмая пересборка разрешена владельцем и идёт сейчас: 137 пар, 17 элементов** —
задача 16, мера текста. Она больше всех шести предыдущих вместе взятых, и потому
спрашивалась отдельно и дважды: сначала «чиним ли вообще» (102 пары по первому
замеру), потом «чиним ли на 137» — когда замер уточнился.

Порядок, который сложился и работает: исполнитель доводит правку до состояния
«эталон разошёлся ровно в тех парах, что ожидались», называет их **поимённо**
и останавливается. Пересобирает после сверки списка. Разошлась чужая пара —
разбираться, а не узаконивать.

## Соглашение об образцах

Образец каждого элемента лежит в константе `ОБР_<ид>` рядом со своей функцией
и подключён к каталогу `CATS` четвёртым элементом кортежа. Пятым идёт
необязательная оговорка — она есть только у `timeline`.

**Литерал не должен встречаться дважды.** На этом спотыкались десять раз:

```bash
grep -n "==null?'[^']\+'" src/elements.js    # запасное значение в тернарнике
```

и глазами: строка из `ОБР_x`, встретившаяся в теле той же функции второй раз.
Цвета берутся из стиля `s` и в образец не входят.

## Что выяснилось и стоит помнить

**Живой сервер держит код на момент запуска.** Node кэширует модули. После
каждого закрытого наряда — `/mcp` и переподключить `svg-library`, иначе
проверяете вчерашний код.

**Предельный вклад — не то же самое, что собственный.** В задаче 16 зазор
поверх исправленного капса давал 44 поля из 58, а сам по себе — три. Вклады
не складываются: в капс-стиле занижений два, и, убрав одно, мера всё равно
занижает, подгонка не срабатывает. Числа «сверх ступени X» без ступени X
не пересказывать.

**Догадку надо мерить, а не обосновывать.** «Капс без таблицы ширин
бессмыслен» звучит убедительно; исполнитель вместо рассуждения проверил,
меняет ли `toUpperCase()` длину строки — на 8658 строках библиотеки не меняет
ни у одной. Получилось тождество, а не мнение.

**Одно понятие — одно определение на весь наряд.** В шестнадцатом ведущий
мерил прописную как `/[А-ЯЁ]/`, а в тексте наряда написал `/[A-ZА-ЯЁ]/`.
Семь пар расхождения из воздуха.

**Путь воспроизведения через настоящего клиента может отличаться от прямого
вызова.** Проба на `Infinity` не проходила через MCP-клиента: он сериализует
аргументы, а `JSON.stringify(1e400)` сам даёт `null` — литерал до сервера
не доезжал. Проба осталась красной **после** правки, и это её и выдало.
Там же: `JSON.stringify(±Infinity)` даёт `null`, поэтому нефинитные значения
уходят в ответ строкой.

**Шрифта Inter нет ни в системе, ни в репозитории**, хотя разметка объявляет
именно его. Рисуется запасной — Segoe UI или SF Pro, смотря у кого. Значит
мера обязана **завышать** ширину: пусть текст ужмётся раньше, чем вылезет.

**Сомнения исполнителей ценнее их основной работы.** Настоящие дефекты
находились именно так: выдуманное число в `retro`, чужой ответ под чужим
вопросом в `faq`, плоские графики у `column` и `area`, пустой пример у `vec`,
ложное предупреждение, палитра, кончавшаяся приглушённым серым.

**Проба, которую не видели падающей, ничего не гарантирует.** Проверка имён
инструментов покрывала половину нужного и пропустила ошибку, уронившую весь
сервер вместе с чужими MCP-серверами сессии: шаблон
`^[a-zA-Z0-9_.-]{1,64}$` проверяет **не только имена инструментов, но и каждый
ключ в `input_schema`** — кириллический ключ роняет весь список инструментов
четырёхсотым ответом.

**Пересказ договора своими словами расходится с договором.** План шесть раз
ошибался в типах и формах полей. Источник истины — `spec/elements.json`.

**`git commit` без указания путей коммитит весь индекс.** За проект чужая
работа попадала в чужой коммит четырежды. Верная форма — `git commit -F <файл>
-- <пути>`, и заметьте порядок: `-F`/`-m` идут **до** `--`.
